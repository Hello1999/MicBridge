# 系统麦克风控制审查与验收

审查日期：2026-09-22。本文记录本次范围、修复与待验条件；历史设备结果不计入本次验收。

## 审查结论

用户需要的是系统麦克风开关。旧实现已经通过全局 AudioManager 与 Root sensor privacy 控制系统，却在开放前后额外读取 ChatGPT AppOps，并把目标包版本纳入校准。应用未安装、权限被拒绝或版本变化会阻碍一个系统级操作，界面同时要求用户理解包名、多个门控和校准。这些依赖与产品任务不一致。

Android 官方说明：支持设备的 Android 12+ 可用一个系统开关控制所有应用的麦克风访问；关闭时应用收到静音音频。系统级控制是合理的产品边界，但系统读回不等于对每个应用录音行为的实时测量。[Android 官方文档](https://developer.android.com/training/permissions/explaining-access)

| 发现 | 本次修复 | 保留的约束 |
| --- | --- | --- |
| 系统控制混入特定应用 AppOps veto | 发布控制移除应用 AppOps、包安装与版本依赖 | AudioManager + sensor privacy 双读回、Root 保护 |
| 用户身份守卫依附应用 veto | 独立核对当前 Android 用户 | 用户变化或身份不明时拒绝 OPEN |

| 返回页面会重复启动并触发屏蔽 | `onResume` 不再重复发出 `ACTION_START` | 服务持续监控权限、网络和保护变化 |
| 本地控制被远程授权或临时闹钟条件阻挡 | 本地不要求 LAN；已验证后的持续恢复不要求精确闹钟 | 核心权限与 Root 监督仍生效；已有远程权限撤销时先 BLOCK |

## 实现边界

- 发布控制器仍为 `audio_manager` 和 `root_sensor_privacy`，两者控制同一系统麦克风范围，不在运行时自动换方案。
- OPEN 需系统两层均明确允许、当前 Android 用户匹配、有效设备验证和 Root 监督。UNKNOWN 只尝试安全方向 BLOCK。
- 校准身份含配置代际、控制器、MicBridge 构建、Android Build ID / fingerprint、Android 用户及校准结构，不含第三方应用包名/版本。
- 测试应用只提供人工声学观察；它必须先能正常录音，才能判断系统屏蔽有效。MicBridge 本身不申请录音权限、不录音。
- 本地首页 toggle 直接走服务，不依赖 HTTP listener / LAN 权限；HTTP 端点与协议兼容。持续 OPEN 无自动截止、不要求精确闹钟；临时验证/诊断 OPEN 继续要求精确闹钟、有限窗口与双 Alarm。
- 本地正常 OPEN 与校准、停服和安全事件共享同步禁止边界，变更前后再次检查；排队的旧本地请求不能跨入校准或停服边界。返回应用只刷新准备状态、唤醒安全监控，不重新启动麦克风流程。
- 当前正常控制不操作应用权限。旧 `targetPackage` 只保留数据兼容；旧 AppOps 元数据仍按“先全局屏蔽、保留当前值、只清元数据”安全收尾。
- `extras/chatgpt-phone-mic` 是独立的历史输入路由扩展，不属于本次系统麦克风控制修复，也未在本次变更。

## 本次真机验收清单

使用本次构建重新记录 Android 型号/API/固件、Root 方案、MicBridge commit 与 APK SHA-256、当前 Android 用户、测试应用、输入路由和网络拓扑。测试应用的名称/版本是结果上下文，不是产品的控制依赖。

1. **不依赖指定应用**：未安装 ChatGPT 的设备仍能启动系统屏蔽与设备验证；安装/卸载/更新第三方应用不改变系统校准身份。不能以目标应用的权限拒绝作为系统控制失败。
2. **系统读回与声音分开**：分别记录 AudioManager、sensor privacy 新鲜读回与实际声音。Root 命令退出码或界面颜色不能代替声学结果。
3. **设备验证**：在有活动录音流且起初真实可收音时验证 OPEN → 仅 Root 屏蔽 → 确认无声并完整 BLOCK → 保存；超时、越序、退出和服务重建均不能保存旧证据。
4. **首页正常使用**：停止时启动屏蔽；通过验证后恢复；开放后立即屏蔽；连续切换遵循服务实时读回，发布验收至少 20 次交替且零状态错位。未知状态与操作中仍可请求屏蔽，失败不显示成功；返回页面不因 `onResume` 重复启动而意外重新屏蔽；未授予 LAN 时仍能完成电池设置并继续本地验证，持续恢复不要求精确闹钟。
5. **跨应用抽查**：用第二个有录音权限的应用复核系统开关影响，确认恢复不改变该应用原有权限。系统 OPEN 而应用无权限时仍应保持无声，不能误报为系统故障。
6. **锁屏与路由**：解锁亮屏、锁屏亮屏、锁屏熄屏及 Doze 分别验证。同一会话恢复、内置麦克风、蓝牙/USB/有线音频与来电按各自场景记录，不相互外推。
7. **身份与故障**：用户/profile 切换、Root 撤销、watcher/supervisor 死亡、进程 kill、Task Manager Stop、Settings Force Stop、重启与网络变化分别验证撤销 OPEN / 尝试 BLOCK / 可信读回与错误呈现。
8. **远程兼容**：iPhone 单次 toggle、请求重放不重复切换、响应 ID/状态校验和振动次数；网络错误必须保持“状态无法确认”。API 31–35 同一 Wi-Fi，API 36+ 热点另验监控条件。
9. **升级与清理**：旧校准失效，旧包名不参与控制，旧 `root_appops` 元数据不会恢复/放宽权限；正常停止和安全移除保护先确认全局屏蔽。
